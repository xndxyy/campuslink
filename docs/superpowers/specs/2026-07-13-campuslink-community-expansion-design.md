# 西大同学 CampusLink 社区扩展设计规格

**日期：** 2026-07-13  
**状态：** 已由用户确认，等待实施计划  
**适用项目：** `outputs/campuslink`  
**品牌名称：** 西大同学 CampusLink

## 1. 文档定位

本文定义 CampusLink 下一阶段的产品级扩展，覆盖品牌、公告、开放邮箱注册、统一发布中心、标签、校园工作、校园论坛、匿名树洞、AI 内容审核和管理员用户管理。

本文是 `2026-07-12-campuslink-design.md` 的增补规格。发生冲突时，以本文为准，尤其包括以下变化：

- 注册不再限制学校邮箱域名，任意有效邮箱均可注册。
- 不提供“西大学生认证”或学生身份徽章。
- 首页从三个栏目扩展为四个栏目，并移除原“刚刚贴上公告板”内容区。
- 原校园工作模型升级，具体工作类型使用标签表达。
- 新增普通论坛、匿名树洞、屏蔽词和 AI 内容审核。
- 新增管理员公告、产品级用户管理和 AI 配置后台。

## 2. 产品定位与边界

CampusLink 是“面向西大学子的开放校园社区”，不是西南大学官方平台，也不声称所有注册用户均为西南大学学生。视觉和文案不得使用官方校徽轮廓，不得出现“官方认证”“仅限西大学生”或“所有用户均为西大学子”等误导性表述。

本阶段包含：

- 学习资源、二手交易、校园工作、校园论坛四个一级栏目。
- 论坛内部的普通论坛和匿名树洞。
- 统一发布中心与统一标签服务。
- 管理员公告、用户管理、屏蔽词、AI 审核设置和审计。
- 二手交易与校园工作的受保护联系方式揭示。

本阶段不包含：

- 站内聊天、私信、群聊或实时消息服务。
- 支付、担保交易、托管、退款或物流。
- 多级评论、关注关系、个性化推荐和私信通知。
- 学生证上传、学校身份核验或学生身份徽章。
- 允许普通用户发布公告。

## 3. 可借鉴的开源项目

- [Lecheeel/sayit](https://github.com/Lecheeel/sayit) 展示了 Next.js 校园社区按业务模块拆分、响应式内容展示和统一用户系统的思路。其 README 声明 MIT 许可证，但本项目只借鉴模块边界和交互思路，不直接复制代码。
- [Born2tweak/BackpackVol2](https://github.com/Born2tweak/BackpackVol2) 展示了校园市集、身份验证、联系方式和实时聊天的常见组合。本项目借鉴交易安全提示，不引入其 Pusher 实时聊天架构；未确认许可证的代码不得复制。

## 4. 用户、角色与访问规则

### 4.1 注册与邮箱验证

- QQ、163、Outlook、学校邮箱等任意合法邮箱均可注册。
- 注册仍需邮箱验证码或一次性验证链接，完成后用户状态才可变为 `ACTIVE`。
- 邮箱验证只证明用户控制该邮箱，不证明其为西大学生。
- 未验证用户可以浏览公开内容，但不能发布、评论、点赞、举报、查看联系方式或进入匿名树洞。
- 已停用用户不能创建会话或执行任何写操作。
- `Campus` 仍作为数据归属边界保留；首发部署把所有开放注册用户归入默认 CampusLink 社区，不再按邮箱域名拒绝注册。
- 现有内部角色值 `STUDENT` 可在兼容期保留，但所有用户界面统一显示“普通用户”，不得显示“已认证学生”。
- `Campus.allowedEmailDomain` 变为不参与准入判断的兼容字段；后台不再把修改校园邮箱域名作为注册控制，完成兼容迁移后再安全移除。

### 4.2 角色

| 角色 | 能力 |
| --- | --- |
| 访客 | 浏览公告、学习资源、二手交易、校园工作和普通论坛公开内容。 |
| 已验证用户 | 发布和管理自己的内容，进入树洞，评论、点赞、举报、收藏和查看受保护联系方式。 |
| `MODERATOR` | 处理内容待审核队列、举报、隐藏与恢复；不能查看树洞真实作者，不能管理用户、公告、AI 密钥或屏蔽词。 |
| `ADMIN` | 拥有审核能力，并可管理用户、公告、标签、屏蔽词、AI 设置和审计日志；仅在树洞存在有效举报时可受审计地解密作者。 |

公告写操作要求 `ADMIN`。首发部署只创建一个有效管理员，即站长本人，因此公告实际上仅由其发布。系统继续禁止停用或降级最后一名有效管理员。

## 5. 品牌与首页

### 5.1 Logo

- 品牌采用“西大同学 CampusLink”。
- Logo 采用已确认的 B 方向“书页山脊”：打开的书页形成重庆山城层次，表达知识流动和地域感。
- Logo 必须原创，不能复刻或暗示西南大学官方校徽。
- 使用 Image2 生成正式素材，交付透明背景主标、深色背景版、浅色背景版和小尺寸图标版。
- 正式生成前需在本地安全配置 EvoLink API Key；密钥不得进入仓库、设计文档、日志或前端代码。

### 5.2 首页结构

首页顺序固定为：

1. 顶部导航和品牌标志。
2. Hero 主文案和统一“发布内容”入口。
3. Hero 最底部的单条公告横幅。
4. 四个并列一级栏目。
5. 页脚安全与非官方声明。

四个栏目为：

| 编号 | 标题 | 首页说明 |
| --- | --- | --- |
| 01 | 学习资源 | 笔记、讲义、课程资料 |
| 02 | 二手交换 | 书籍、设备、生活用品 |
| 03 | 校园工作 | 通过预设标签和自定义标签表达具体类型 |
| 04 | 校园论坛 | 话题讨论、校园互助、匿名树洞 |

删除当前首页“刚刚贴上公告板”区域，避免与正式公告重复。

## 6. 公告系统

### 6.1 管理体验

- 管理后台侧栏新增 `/admin/announcements`。
- 发布表单包含标题、纯文本正文、可选封面图和置顶开关。
- 公告立即发布，不提供草稿、定时发布或普通用户投稿。
- 每个 Campus 最多一条置顶公告；置顶新公告时在同一数据库事务中取消旧置顶。
- 永久删除采用二次确认弹窗，显示公告标题并明确“不可恢复”。

### 6.2 公共展示

- 首页 Hero 底部只展示置顶公告；没有置顶时展示最新公告。
- “查看全部公告”进入 `/announcements`。
- 公告中心按置顶优先、发布时间倒序展示。
- 桌面端点击历史公告打开右侧详情抽屉；移动端打开全屏面板。
- 选择状态写入查询参数，例如 `/announcements?announcement=<id>`，保证刷新、前进后退和分享链接可恢复。
- 详情显示对应正文和封面图；未上传封面时使用品牌占位图。

### 6.3 永久删除

删除公告时：

1. 数据库事务删除公告及关联 `Asset` 记录。
2. 同一事务写入最小 `ANNOUNCEMENT_DELETED` 审计事件，只保留公告 ID、操作者、时间和是否存在封面，不保留标题、正文、存储键或图片地址。
3. 同一事务创建对象存储删除任务。
4. 提交后立即尝试删除对象；失败时由内部清理任务重试，直到对象不存在。

## 7. 统一发布中心与标签

### 7.1 发布中心

顶部“发布内容”按钮改为 `/submit`。该页面提供五个入口：

1. 学习资源。
2. 二手交易。
3. 校园工作。
4. 普通论坛帖子。
5. 匿名树洞。

学习资源表单移除课程代码字段。数据库迁移先停止读写该字段，再在兼容阶段结束后删除列。

### 7.2 标签规则

学习资源、二手交易和校园工作均支持：

- 管理员维护的预设标签。
- 用户自定义标签。
- 每条内容最多五个标签，其中最多两个自定义标签。
- 标签大小写、全半角、首尾空格和连续空格统一规范化后去重。
- 自定义标签必须通过长度、纯文本、屏蔽词和 AI 审核。
- 自定义标签不会自动成为全站预设；管理员可在后台将高频合规标签提升为预设。
- 预设标签被停用后不能用于新内容，但历史内容仍可正常显示。

校园工作首批预设标签包含 `COS委托`、`校园跑腿`、`临时兼职`、`技能服务` 和 `其他`。

## 8. 校园工作与交易沟通

原 `JobPost` 产品语义升级为 `CampusWorkPost`，公共地址使用 `/campus-work`，旧 `/jobs` 和 `/jobs/[id]` 通过永久重定向保持兼容。

校园工作表单包含：

- 标题。
- 详细介绍。
- 地点。
- 报酬说明。
- 预设与自定义标签。
- 受保护联系方式。

不开发站内聊天。二手交易和校园工作沿用同一联系方式模式：

- 公共列表和详情响应不包含联系方式。
- 已验证且状态正常的用户点击“联系发布者”后，服务端再次鉴权并返回联系方式。
- 每次查看写入审计事件。
- 页面提示优先在校内公共区域见面、不提前转账，并明确平台不提供担保支付。

## 9. 校园论坛

### 9.1 普通论坛

- `/forum` 默认显示普通论坛，普通论坛内容可公开阅读。
- 已验证用户可发帖、一级评论、点赞和举报。
- 不提供多级回复；评论只直接属于帖子。
- 帖子支持管理员维护的话题分类、搜索和稳定分页。
- 作者可以编辑或删除自己的帖子和评论；存在审核处理或证据保留要求时，管理员可隐藏而不是物理删除。

### 9.2 匿名树洞

- `/forum` 内提供“匿名树洞”标签页。
- 只有邮箱已验证且状态正常的用户可以阅读、发布、点赞和举报树洞。
- 树洞不开放评论；该规则同时由 UI、API 和领域服务强制执行。
- 普通用户看到的是每帖随机编号，不显示姓名、头像、主页链接或可跨帖子关联的作者标识。
- 用户可以在“我的发布”中管理自己的树洞，但公共页面不暴露身份。

树洞身份采用两项服务端数据：

- 使用独立密钥和带认证加密保存的作者身份密文。
- 使用独立 HMAC 密钥生成的不可逆防滥用指纹，用于频率限制、自主管理和重复行为检测。

只有帖子存在有效举报并进入审核流程时，`ADMIN` 才能填写原因并调用作者解密接口。每次解密都写入独立审计事件。`MODERATOR`、普通页面、列表查询、导出和日志均不得返回真实作者。

## 10. 屏蔽词与 AI 内容审核

### 10.1 覆盖范围

本地屏蔽词和 AI 审核覆盖所有普通用户公开内容：

- 学习资源标题、摘要和自定义标签。
- 二手交易标题、说明、地点和自定义标签。
- 校园工作标题、说明、地点、报酬和自定义标签。
- 普通论坛帖子与评论。
- 匿名树洞。

私密联系方式、邮箱、树洞真实身份和文件内容不得发送给外部 AI。管理员公告不经过 AI 自动拦截，但仍按纯文本、长度和 HTML 禁止规则校验。

### 10.2 屏蔽词

- 管理后台新增 `/admin/blocked-words`。
- 屏蔽词只支持纯文本词条，不允许管理员提交任意正则表达式。
- 匹配前执行大小写、全半角、空白和常见分隔符规范化。
- 命中后立即阻止发布，提示用户修改，不自动替换为 `***`。
- 管理员可新增、启停和删除词条，并填写管理原因；所有变更进入审计日志。
- 用户反馈说明违规类别和修改方向，但不公开完整词库或内部匹配策略。

### 10.3 AI 设置

管理后台新增 `/admin/ai-settings`，仅 `ADMIN` 可访问。配置项包括：

- 启用状态。
- OpenAI-compatible Base URL。
- 模型名。
- API Key。
- 请求超时时间。
- `PASS`、`REVIEW`、`BLOCK` 风险边界。

Base URL 在生产环境必须使用 HTTPS，不能包含用户名或密码，并必须命中运维配置的允许域名列表。解析后的所有 IP 都要拒绝回环、链路本地、私网和保留地址，重定向后的目标也要重新校验，防止 SSRF。需要接入内网自建模型时，由运维显式配置允许主机，而不是在页面中绕过限制。

API Key 使用独立的服务端加密密钥进行带认证加密。页面保存后只显示末四位，不返回原文；日志、错误、审计、导出和前端状态均不得包含密钥。配置页提供“测试连接”，测试只发送固定样例，不发送真实用户内容。

### 10.4 AI 结果与用户反馈

模型必须返回服务端验证的结构化 JSON：

- `decision`: `PASS | REVIEW | BLOCK`。
- `riskScore`: `0-100`。
- `categories`: 受控违规类别数组。
- `reasonZh`: 简短中文原因。
- `suggestionZh`: 可执行的修改建议。
- `adminSignals`: 仅管理员可见的判断依据，不包含内部提示词。

处理规则：

- `PASS`：满足其他业务门禁后发布。
- `REVIEW`：保存为待人工审核，暂不公开。
- `BLOCK`：保存为已拒绝，用户可查看违规类别、简短原因和修改建议，修改后重新提交。
- 用户反馈不显示内部系统提示词、完整屏蔽词库或 AI 原始响应。

AI 超时、连接失败或返回格式无效时，按用户确认的可用性优先策略处理：只要本地屏蔽词和其他硬性校验通过，内容继续发布，同时写入 `AI_CHECK_SKIPPED`，管理后台显示告警。该降级绝不绕过文件安全扫描、邮箱验证、权限、频率限制或所有权检查。

## 11. 管理员用户管理

`/admin/users` 升级为产品级用户管理：

- 按姓名或邮箱搜索。
- 按角色、状态和邮箱验证状态筛选。
- 稳定分页，不再只显示无法继续翻页的前 25 名用户。
- 点击用户行打开右侧详情抽屉，移动端使用全屏面板。
- 详情包含账号概览、发布摘要、举报摘要、处罚摘要和相关审计记录。
- 管理动作包括调整角色、停用/恢复账号和强制退出全部设备。
- 每个高风险操作必须填写原因并二次确认。
- 降权、停用或强制退出会撤销全部有效 Session。
- 未验证或非 `ACTIVE` 用户不能成为 `MODERATOR` 或 `ADMIN`。
- 禁止降级或停用最后一名有效管理员。
- 不提供用户永久删除，避免破坏内容归属、举报证据和审计链。

## 12. 数据模型与领域边界

新增或调整的主要模型：

| 模型 | 作用 |
| --- | --- |
| `Announcement` | 管理员公告、置顶、正文、发布时间和封面关联。 |
| `StorageDeletionJob` | 数据库提交后可靠重试对象存储删除。 |
| `CampusWorkPost` | 替代 `JobPost` 产品语义，增加标签和受保护联系方式。 |
| `TagDefinition` | 按 Campus 和内容类型维护预设标签。 |
| `ResourceTag`、`MarketplaceTag`、`CampusWorkTag` | 使用外键保证标签与内容关联完整性。 |
| `ForumPost` | 区分 `DISCUSSION` 与 `TREE_HOLE`，保存状态和审核结果。 |
| `ForumComment` | 只允许关联 `DISCUSSION` 帖子的一层评论。 |
| `ForumLike` | 用户与帖子的唯一点赞关系。 |
| `BlockedWord` | 管理员维护的本地阻断词条。 |
| `AiModerationConfig` | 加密保存模型连接配置和风险设置。 |
| `ContentAssessment` | 保存 AI 决策、类别、用户反馈、模型和执行状态，不保存 API Key。 |

扩展 `AssetKind`、举报目标、收藏目标、审核目标和审计目标，使其覆盖公告、校园工作、论坛帖子与评论。领域服务按公告、标签、论坛、匿名身份、AI 审核和用户治理拆分；页面与 Route Handler 只负责鉴权、请求边界、调用服务和安全响应映射。

## 13. 安全与隐私

- 所有写请求校验 Session、邮箱验证状态、角色、所有权、同源 `Origin`、请求体大小和频率限制。
- 用户文本按纯文本渲染，不执行 HTML、Markdown HTML 或 `javascript:` 内容。
- 屏蔽词、AI 和管理员审核不能替代服务端权限与数据约束。
- AI 配置密钥和树洞身份密钥必须是不同的环境密钥，并支持密钥版本字段以便轮换。
- 审计详情经过递归脱敏，过滤密码、Token、Secret、联系方式、邮箱和密钥字段。
- 联系方式只通过受保护接口揭示，不能出现在列表、SSR 页面数据、搜索索引或客户端预取响应中。
- 树洞身份不能出现在普通 Prisma `include`、日志、监控标签或错误对象中。
- 自定义 AI Base URL 按 SSRF 防护规则解析和校验，禁止仅依赖字符串前缀判断。
- 上传继续使用私有对象存储、短期签名 URL、内容类型/大小限制和恶意文件扫描门禁。

## 14. 错误与降级处理

- 数据库、邮件、对象存储和 AI 错误返回稳定中文提示，不暴露堆栈、供应商响应或配置。
- 邮件失败保留可重试的待验证账号，不伪造验证成功。
- 公告封面删除失败进入 `StorageDeletionJob`，公告本身不会重新公开。
- AI `REVIEW` 和 `BLOCK` 都保存可追踪状态，避免用户重复提交后无法理解结果。
- AI 不可用按已确认的 fail-open 规则发布，但必须产生后台可见告警和审计事件。
- 重复点赞、重复举报、并发置顶、并发最后管理员变更和重复身份解密使用唯一约束或串行化事务处理。
- 页面为加载、空数据、无权限、被隐藏、已删除、审核中和依赖暂不可用提供独立状态。

## 18. 迁移顺序

实施采用 expand/contract 顺序：

1. 增加新枚举、新表、新可空字段和新索引，不删除旧结构。
2. 增加开放邮箱逻辑、统一发布中心和新路由，同时保留旧 `/jobs`。
3. 迁移 `JobPost` 数据到校园工作语义并验证数量、所有权和状态。
4. 上线公告、标签、论坛、树洞、屏蔽词和 AI 配置。
5. 完成读写切换和兼容重定向。
6. 验证生产数据与备份后，移除课程代码和其他废弃字段。

每一步都必须有可回滚发布边界，不能把不可逆删除与首次新代码发布放在同一迁移中。

## 19. 验收标准

满足以下条件才视为本扩展交付完成：

- 首页、Logo、公告和四栏目与已确认界面一致并适配移动端。
- 任意邮箱可注册，未验证用户不能执行受保护操作。
- `/submit` 能正确进入五类发布流程，学习资源不再显示课程代码。
- 三类业务内容都支持预设与自定义标签，限制和审核有效。
- 普通论坛支持一级评论；树洞仅验证用户可见且不存在可调用的评论接口。
- 普通用户和审核员无法获得树洞作者；管理员只有在有效举报下才能受审计地解密。
- 屏蔽词始终本地执行，AI 三级结果和中文反馈符合设计，AI 不可用时产生明确告警。
- AI API Key、私密联系方式和匿名身份不通过任何公共响应或日志泄漏。
- 公告永久删除正文、数据库记录和封面对象，只保留最小审计事件。
- 用户管理具备搜索、筛选、分页、详情、停用、强制退出和审计。
- 全部自动化验证和 production build 通过，部署文档反映新环境变量、任务、备份和风险。
