# CampusLink 治理、发布与中文化设计

日期：2026-07-17

## 1. 目标

本轮改造同时解决以下生产问题：

- 自动部署基础屏蔽词，管理员可维护词库并暂停或启用 AI 审核。
- AI 暂停时保留本地屏蔽词拦截，其余内容自动公开。
- 将公开界面、认证流程、邮件和错误提示统一为中文。
- 修复验证邮件重发，并让新链接替代旧链接。
- 将首页说明文案稳定排成两行，并让短页面页脚位于窗口底部。
- 将发布分类置于页面上方，填写区域置于下方。
- 为学习资源、二手交易和校园工作部署预设标签。
- 学习资源允许纯文字发布，内容说明无最少字数且附件可选。
- 删除指定的发布页说明文案。
- 让用户可删除自己的全部类型内容，同时保护未处理举报证据。
- 将笼统的英文校验错误替换为可定位的中文错误。

不在本轮范围内：统一所有内容表为单一数据模型、引入完整第三方 i18n 框架、改变论坛匿名身份模型。

## 2. 设计原则

- 沿用现有 Next.js、Prisma、PostgreSQL、MinIO、systemd 和 Caddy 架构。
- 复用现有标签、屏蔽词、审核、审计和对象清理边界，不引入大型依赖。
- 用户删除与证据销毁分离：内容可立即撤下，但未处理举报的证据必须保留。
- 生产初始化与演示数据分离，不在生产运行创建演示用户的 `prisma/seed.ts`。
- 所有写操作继续校验同源请求、登录状态、校园和资源所有权。

## 3. 发布工作区

### 3.1 页面结构

发布页采用统一的 `PublishWorkspace` 外壳：

1. 页面顶部为五个分类标签：学习资源、二手交易、校园工作、校园论坛、匿名树洞。
2. 当前分类在同一页面下方显示对应表单。
3. 原有 `/submit/resource`、`/submit/marketplace`、`/submit/campus-work`、`/submit/forum` 和 `/submit/tree-hole` 地址继续可访问，并渲染相同外壳与正确的激活分类。
4. 标题使用紧凑层级，不再使用会在常见视口中断成多行的超大字号。
5. 不在表单外嵌套装饰卡片；分类栏和填写区域是两个清晰的全宽区段。

从对应页面删除以下说明：

- “上传至少一份文档。所有内容在公开前都会由校园审核员检查。”
- “清楚描述物品与取货区域。联系方式只保存于受保护记录，不会公开展示。”
- “说明工作内容、地点、报酬与联系方法，标签最多选择五个。”
- “使用真实校园昵称参与公开讨论，帖子支持评论、点赞与举报。”

### 3.2 学习资源规则

- 标题仍为必填，长度保持 3 到 200 个字符。
- 内容说明改为可选，去除 20 字最小限制，最大仍为 5000 个字符。
- 内容说明留空时在现有非空数据库字段中保存为空字符串，不把字段改为可空类型。
- `assetIds` 允许空数组，最多 8 个附件。
- 文档和图片均为可选，因此纯文字资源可以发布。
- 用户选择附件后，仍执行文件类型、大小、所有权、上传状态和文档扫描校验。
- 创建和重新提交草稿时不再要求必须存在 `RESOURCE_DOCUMENT`。
- 二手交易的图片要求保持现状；本轮“附件可选”只针对学习资源。

### 3.3 精确校验反馈

服务端返回稳定的中文错误代码和字段错误，客户端在对应控件附近显示：

- 标题为空或过长。
- 内容说明过长或含不允许的 HTML。
- 附件数量、类型、状态或所有权不正确。
- 预设标签不存在、已停用或不属于当前校园/分类。
- 自定义标签重复或标准化后冲突。
- 标签总数超过 5 个。

两个自定义标签相同时，客户端在请求前提示“自定义标签不能重复，请修改第二个标签”，服务端仍执行相同校验，不能只依赖前端。

## 4. 预设标签与屏蔽词初始化

### 4.1 预设标签

默认标签如下：

- 学习资源：课程笔记、课件讲义、试题题库、学习工具、经验分享、其他。
- 二手交易：教材书籍、数码设备、生活用品、宿舍用品、运动户外、免费赠送、求购、其他。
- 校园工作：校园跑腿、临时兼职、家教辅导、活动协助、技能服务、设计摄影、其他。

部署迁移为当前所有启用校园插入缺失标签，并使用校园、分类和 slug 唯一键避免重复。迁移只执行一次，因此管理员之后停用标签不会被发布重启重新启用。开发与测试种子复用同一份标签定义。

### 4.2 基础屏蔽词

自动部署一份保守的基础词库，分类覆盖违法内容、诈骗引流、色情内容、暴力威胁、人身攻击、隐私泄露和恶意推广。词库以可审计数据写入 `BlockedWord`，不硬编码在请求处理函数中。

管理员可以：

- 添加词语、类别和治理原因。
- 单独启用或停用词语。
- 永久删除词语。
- 查看当前启用状态。

所有变更继续写入审计日志。屏蔽词缓存最长 60 秒，变更后主动失效当前校园缓存，使管理员操作尽快生效。

## 5. AI 审核开关

管理员后台显示明确状态：

- 启用：本地屏蔽词先检查，再调用 AI；AI 结果可通过、转人工或拦截。
- 暂停：本地屏蔽词仍检查；未命中屏蔽词的内容直接通过并公开，不进入人工审核。

暂停和重新启用均要求治理原因并写审计日志。暂停状态不删除 API 配置，重新启用后可直接恢复。AI 服务故障仍按现有故障策略记录，不能伪装为正常审核结果。

## 6. 用户删除内容

### 6.1 支持范围

“我的发布”为学习资源、二手物品、校园工作、普通论坛和匿名树洞提供删除按钮。草稿、待审核、已发布、被拒绝、已隐藏和已归档状态均可请求删除。

### 6.2 删除流程

1. 客户端显示二次确认，并说明删除不可撤销。
2. 使用 HTTP `DELETE` 调用对应内容路由。
3. 服务端校验同源、已验证账号、校园和内容所有权。
4. 在事务内锁定目标并查询 `OPEN` 或 `TRIAGED` 举报。
5. 没有未处理举报时，先为关联对象创建存储删除任务，再删除内容记录；外键级联清理标签关系、收藏、点赞、评论和其他从属记录。
6. 存在未处理举报时，将内容改为不可公开状态并记录 `ownerDeletionRequestedAt`，从公开页和“我的发布”隐藏，但保留处理证据。
7. 举报处理完成后，治理流程检测删除请求并完成数据库与对象存储清理。

资源、二手、校园工作和论坛帖子使用一致的返回结构：`deleted`、`archived` 和中文 `message`。论坛现有的举报保护删除逻辑保留并对齐该结构。

## 7. 邮件、认证与中文化

- 注册、登录、邮箱验证、重新发送邮件及其错误状态全部使用中文。
- 邮件标题、纯文本正文和 HTML 正文使用中文。
- 验证链接统一从规范站点地址 `https://swuerlink.top` 生成。
- 重发验证邮件时在事务内使旧 token 失效，并只保留新 token。
- 成功后显示“验证邮件已发送，请检查收件箱和垃圾邮件”，并启动 60 秒重发倒计时。
- 速率限制、未知邮箱和邮件服务失败返回不泄露账户存在性的中文提示。
- 保留 `CampusLink`、`API Key`、模型名称等必要专有名词，其他用户可见英文全部翻译。

## 8. 首页与页脚

桌面端首页说明采用确认的 A 方案：

```text
CampusLink 是面向西大学子的校园公共空间。
公开内容经过审核，匿名树洞也为表达保留边界。
```

两个完整句子各占一行，“边界”不落到第三行。移动端允许自然换行，避免压缩字号。根布局使用纵向弹性结构，主内容占据剩余高度，使短页面的页脚位于视口底部，长页面则正常随内容向下。

## 9. 数据流与失败处理

- 发布：客户端字段校验 -> 同源与身份校验 -> Zod 中文字段校验 -> 标签与附件所有权校验 -> 屏蔽词 -> 可选 AI -> 事务写入 -> 中文结果。
- 删除：二次确认 -> 所有权与举报查询 -> 删除或证据保留 -> 对象清理队列 -> 中文结果。
- 邮件重发：速率限制 -> token 替换 -> SMTP 发送 -> 倒计时；发送失败不显示成功状态。
- 初始化：Prisma 迁移 -> 生产默认数据迁移 -> 应用构建与启动；不运行演示种子。

所有跨数据库和对象存储的删除继续使用“事务内排队、提交后异步删除”的方式，避免数据库回滚后对象已经丢失。

## 10. 测试与验收

单元测试：

- 学习资源允许空说明、短说明和零附件。
- 已提供附件时仍拒绝非法类型、未就绪、非本人附件和未通过扫描的文档。
- 重复自定义标签返回具体中文错误。
- 默认标签与屏蔽词定义唯一且分类正确。
- AI 暂停时屏蔽词仍拦截，普通内容得到发布结果。

集成测试：

- 三类内容的创建、编辑、重新提交和删除。
- 所有状态下只能删除本人内容。
- 无举报时硬删除并创建附件清理任务。
- 有未处理举报时撤下并保留证据，举报处理后完成清理。
- 邮件重发替换旧 token，旧链接失效，新链接有效。

端到端与视觉验收：

- 桌面和手机视口完成五类发布流程。
- 分类在上、表单在下，标签可选且没有横向溢出。
- 首页桌面严格两行，移动端可读，页脚位置正确。
- 全部认证、发布和管理员关键界面无意外英文。
- 生产部署后验证迁移状态、默认标签、屏蔽词、AI 开关、SMTP 和删除流程。

## 11. 发布顺序

1. 合并代码并完成测试、类型检查和生产构建。
2. 备份数据库并部署新版本。
3. 执行 Prisma 迁移和一次性默认数据迁移。
4. 重启应用与相关清理 worker/timer。
5. 验证预设标签和屏蔽词已创建且没有重复。
6. 冒烟测试发布、删除、AI 暂停、邮件重发、首页和页脚。
7. 检查日志与队列指标后恢复正常运营。
