# CampusLink 单行导航、论坛分类与二手价格筛选设计

状态：已由用户确认，等待实施计划。

## 1. 背景与范围

本设计统一处理三个相互关联的界面调整：全站顶部入口重排、论坛与树洞共享预设分类、二手交易价格区间筛选。它取代 `2026-07-17-campuslink-two-tier-header-design.md` 中的双层顶部方案；旧文档仅保留为历史记录。

目标：

- 桌面端和手机端均将全部全站入口放在同一行顶部。
- 保留首页下方四个大型内容入口及首页当前水平留白。
- 论坛讨论与匿名树洞共用七个数据库分类，并继续使用下拉筛选。
- 移除论坛和树洞页的重复发布按钮，统一从全站“发布内容”进入。
- 二手交易的最低价和最高价始终并排，用户以“元”输入金额。

非目标：

- 不修改认证、论坛权限、匿名身份、审核或举报逻辑。
- 不为论坛分类增加讨论/树洞范围字段。
- 不增加分类卡片、标签导航或分类管理功能。
- 不移动首页品牌或正文的现有左边界。
- 不删除首页下方的四个大型内容入口。

## 2. 顶部导航设计

### 2.1 信息顺序与路由

顶部使用一个不换行的水平轨道，顺序固定为：

1. 品牌：`/`
2. 学习资源：`/resources`
3. 二手交易：`/marketplace`
4. 校园工作：`/campus-work`
5. 校园论坛：`/forum`
6. 我的发布：`/me/submissions`
7. 我的收藏：`/me/favourites`
8. 发布内容：`/submit`

“校园论坛”是唯一的论坛顶部入口。用户进入 `/forum` 后，继续使用现有“校园论坛/匿名树洞”页内标签切换两种视图。

“发布内容”保持绿色主按钮样式；其他入口使用文字链接，个人入口使用较弱的次级文字颜色。全站只维护一份入口定义，不为桌面端和手机端复制两套链接。

### 2.2 响应式行为

- 桌面端完整显示单行轨道，不恢复第二行导航。
- 窄屏仍保持同一行，轨道使用原生 `overflow-x: auto` 横向滚动。
- 每个入口使用稳定的内容宽度、`white-space: nowrap` 和 `flex: 0 0 auto`，禁止压缩文字或产生重叠。
- 窄屏品牌显示校徽与 `CampusLink`；桌面端显示校徽与“西大同学 CampusLink”。
- 横向滚动使用滚动吸附，并保留可见的原生或定制滚动位置提示。
- 键盘聚焦后浏览器应自动将对应链接滚入可视区域；焦点样式不得被滚动容器裁切。
- 保留现有跳转到主要内容的 skip link 和语义化导航标签。

首页品牌与正文继续使用当前各自的水平留白，不引入新的共享左边线。首页下方 `category-strip` 保持现有内容、顺序和响应式布局。

## 3. 论坛与树洞设计

### 3.1 统一发布入口

从论坛列表页标题区删除“发布讨论”，从匿名树洞列表页标题区删除“发布树洞”。标题区只保留眉题、标题和说明文字。

`/submit/forum` 与 `/submit/tree-hole` 路由继续存在，供统一发布中心分流和已有深链接使用；仅删除列表页上的重复入口。用户可从顶部“发布内容”进入 `/submit`，再选择论坛讨论或匿名树洞。

### 3.2 共享预设分类

论坛讨论与匿名树洞继续共用当前 `ForumCategory` 模型，不增加范围字段。预设分类为：

| 标签 | slug |
| --- | --- |
| 校园生活 | `campus-life` |
| 学习互助 | `study-help` |
| 失物招领 | `lost-and-found` |
| 兴趣交流 | `interests` |
| 求助建议 | `help-and-advice` |
| 情感交流 | `emotional-support` |
| 其他 | `other` |

列表筛选和两个发布表单继续查询当前校园中 `isActive = true` 的分类。列表页保留现有分类下拉框，不改为可见标签栏。

上表定义分类集合，不引入新的排序字段。下拉框继续使用现有的 `label`、`id` 数据库排序规则。

### 3.3 数据迁移与种子数据

新增一条前向 Prisma SQL 迁移，为数据库中的每个校园插入七个预设分类。迁移按 `campusId + slug` 冲突更新 `label`、`isActive` 和 `updatedAt`，因此重复执行不会生成重复数据，也不会依赖生产校园的固定 ID。

`prisma/seed-data.ts` 同步为相同七项。种子 upsert 的更新分支同步名称和启用状态，避免已有开发数据库继续保留旧标签或禁用状态。

该变更不修改 Prisma 模型。回滚应用代码时不删除分类记录，因为已有帖子可能引用这些 slug。

## 4. 二手交易价格筛选

### 4.1 布局

检索框继续位于筛选条件上方。二手交易筛选区使用固定的两列网格：

- 第一排：状态、标签。
- 第二排：最低价（元）、最高价（元）。

桌面端与手机端都保持最低价和最高价并排。只有二手交易使用该专用网格；学习资源和校园工作的筛选布局不受影响。

### 4.2 金额语义与转换

浏览器表单和 URL 查询参数使用 `minPrice`、`maxPrice`，单位为元。领域服务和数据库继续使用整数 `minPriceCents`、`maxPriceCents`。

新表单不再生成旧的 `minPriceCents`、`maxPriceCents` URL 参数；这些名称只保留在应用内部的领域查询对象中，不作为浏览器查询参数兼容。

转换规则：

- 空字符串转换为 `undefined`。
- 只接受非负十进制字符串，整数部分必填，小数部分最多两位。
- 通过拆分整数和小数文本、补齐两位小数后组合为整数分，不使用浮点数乘法。
- 转换后的值不得超过现有 `MAX_PRICE_CENTS`。
- 两项都存在时，`maxPriceCents` 必须大于或等于 `minPriceCents`。

输入无效时保留用户填写的原始值，显示中文行内错误并跳过数据库列表查询。验证错误不得继续显示为“数据库暂时不可用”。

## 5. 代码边界

- `app/layout.tsx`：将现有品牌行、产品导航和个人导航收敛为单一水平轨道，复用 `SiteBrand`。
- `app/globals.css`：定义单行轨道、横向滚动、滚动提示、稳定入口尺寸和价格两列网格；保留首页现有水平留白。
- `components/forum/forum-list.tsx`：删除列表页发布按钮，保留页内视图标签和下拉筛选。
- `prisma/seed-data.ts` 与新迁移：提供七个共享预设分类。
- `lib/validation/content.ts`：接收元单位查询值、执行字符串到整数分的转换和价格区间校验。
- `lib/domain/public-content.ts`：区分查询验证错误与数据库错误，并向页面返回可恢复的中文验证信息。
- `components/content/public-list.tsx`：使用元单位字段和二手交易专用 2x2 筛选网格，保留无效输入供用户修正。

不新增通用导航框架、客户端全局状态或分类范围抽象。

## 6. 错误处理与可访问性

- 价格错误使用 `role="alert"` 或等价的可访问状态区域，并与对应筛选表单关联。
- 空价格不是错误；负数、超过两位小数、超上限和反向区间分别使用明确中文信息。
- 横向导航支持触摸、鼠标滚轮/触控板和键盘焦点，不依赖拖拽脚本。
- 链接文字保持完整可读，不通过随视口变化的字号缩放解决空间不足。
- Prisma 迁移失败时保持标准部署失败行为，不允许应用在分类迁移未完成时被标记部署成功。
- 论坛分类读取失败时沿用现有论坛加载错误状态，不回退到代码硬编码分类。

## 7. 测试与验收

自动化测试至少覆盖：

- 元到分：整数、一位小数、两位小数、零和允许上限。
- 非法金额：负数、三位小数、非数字、超上限和最高价低于最低价。
- `loadPublicList` 不把价格验证错误误报为数据库故障，也不执行列表查询。
- 二手查询传入领域服务的仍是整数分。
- 七个种子分类的 slug、名称和启用状态正确，重复 seed 不产生重复项。
- 顶部八项顺序和路由正确，只有“发布内容”使用主按钮样式。
- 论坛与树洞列表不再渲染“发布讨论/发布树洞”，页内视图切换仍存在。
- 论坛和树洞列表、发布表单都读取相同的启用分类。

浏览器验收视口至少包括桌面 `1440x900` 和手机 `390x844`：

- 顶部轨道的内容高度始终为一行，无文字重叠或纵向换行。
- 手机端 `scrollWidth > clientWidth`，可横向到达最后的“发布内容”，焦点遍历也可到达所有入口。
- 首页原有品牌和正文水平位置未发生变化，下方四个大型入口仍可见。
- 二手筛选中最低价和最高价具有相同纵向位置且保持并排。
- 论坛标题区无独立发布按钮，分类下拉框包含七项共享分类。

完成后运行项目现有格式检查、lint、类型检查、单元/集成测试与端到端测试。使用 Playwright 截图核对桌面端和手机端实际布局。

## 8. 发布与回滚

先执行分类迁移，再启动新应用版本。部署后依次检查首页、二手交易、论坛讨论、匿名树洞、统一发布中心、我的发布和我的收藏。

界面代码可独立回滚；七个分类数据保留，不执行删除式回滚。金额查询没有数据迁移，数据库仍以整数分存储。

## 9. 已拒绝方案

- 双层顶部导航：不符合最终确认的桌面和手机均单行要求。
- 手机端折成两行：不符合最终确认的整行横向滚动要求。
- 论坛与树洞分别维护分类：用户选择共用一套分类。
- 分类可见标签栏：用户选择保留下拉框。
- 代码硬编码分类：会造成数据库、校验和页面选项不同步。
- 用户直接输入“分”：暴露内部金额存储细节，不符合中文交易场景。
